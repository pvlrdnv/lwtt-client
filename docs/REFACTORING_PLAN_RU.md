# План повышения стабильности LW TrustTunnel Client

Дата: 24 ноября 2026 года. Базовая версия: 4.16.

Первый приоритет – исправить редактирование полей и исключить потерю настроек и подключения. Затем добавить согласованный общий список обхода VPN и постепенно разделить интерфейс, конфигурацию и управление процессами.

Обход VPN включён в план по решению владельца. Остальные пункты – предложения по результатам анализа исходников. Поведение WinForms, UAC и сетевых маршрутов необходимо проверить на Windows 10/11; ниже отдельно указаны подтверждённые особенности кода и эксплуатационные риски.

## Результат реализации

Изменения реализованы в версии 4.17. Замечания ниже описывают исходное состояние версии 4.16; номера строк относятся к ней. Реализация разделена на модули хранения, конфигурации, подключения, обмена командами менеджера и окна обхода VPN.

- [x] Исправлен ввод: поля остаются прикреплёнными к сетке, валидация отделена от размещения, изменения размеров объединяются через BeginInvoke.
- [x] Переходы учитывают несохранённый ввод; повторное открытие менеджера передаёт команду существующему окну через атомарный файловый почтовый ящик.
- [x] Сохранение меняет только управляемые поля TOML. Дополнительные настройки, резервные адреса и ручные исключения сохраняются. Escape-последовательности паролей читаются последовательно.
- [x] Файлы сохраняются атомарно с журналом отката; переименование и удаление профиля входят в общую транзакцию.
- [x] Подключение, отключение, проверка и восстановление выполняются фоновым координатором под общей блокировкой. Отмена проверки не убивает worker и проходит через восстановление.
- [x] Готовность туннеля определяется по сообщению TrustTunnel v1.0.49, а не только по процессу. Состояние читается из журналов постепенно, включая длинные журналы и незавершённые строки.
- [x] Неудачная остановка не разрешает замену конфигурации. При сбое запуска восстанавливается предыдущая конфигурация; при аварии worker доступно восстановление из трея.
- [x] Процессы проверяются по пути текущей установки. Массовая остановка по имени удалена.
- [x] Общий список обхода VPN реализован в трее. Он сохраняется отдельно от профилей и объединяется с ручными исключениями только при запуске.
- [x] Улучшены проверки адресов, портов, импорта и начала срока сертификата. Повреждённые профили отображаются с ошибкой.
- [x] Исправлены аргументы запуска, обнаруженные ошибки типов иконок и Windows-сборщик. Оба сборщика используют закреплённую версию движка, SHA256 и явный список публичных файлов.
- [x] Журналы менеджера ограничены по размеру, старые сессии клиента и временные задания очищаются. Экспорт диагностики скрывает известные учётные данные; журнал восстановления остаётся локальным.
- [x] Обновлены версия, инструкции и сборка ZIP с корректными UTF-8-именами файлов.

## Редактирование без мигания и потери фокуса

### Поля удаляются из формы при каждом символе

**Приоритет: высокий. Цепочка вызовов подтверждена кодом; визуальный результат нужно повторно проверить на Windows.**

Источник: `app/lwtt_app/lwtt_manager.ps1`, обработчики `TextChanged` около строки 3566, `Update-EditorValidation` (1165), `Update-EditorContentLayout` (3175), `Update-AdvancedGridLayout` (3119).

Каждый символ вызывает проверку всей формы, затем пересчёт расположения элементов. Внутри пересчёта выполняются `advancedGrid.Controls.Clear()` и повторное добавление контейнеров с полями. Поле с курсором временно отсоединяется от формы. Это непосредственно объясняет наблюдаемую потерю фокуса и является сильным кандидатом на причину мигания. `SuspendLayout()` при этом не отменяет удаление элементов.

Исправление: создать поля один раз. Отделить проверку данных от размещения элементов. При вводе обновлять только сообщения и доступность кнопок; перестраивать сетку лишь при переходе между одной и двумя колонками. При обычном изменении ширины менять размеры существующих элементов. Сохранять курсор, выделение и прокрутку при необходимом перестроении. Двойную буферизацию рассматривать после устранения пересоздания структуры формы.

Дополнительно: обработчики изменений должны учитывать `LoadingEditor`. Сейчас этот флаг подавляет отметку о несохранённых изменениях, но не повторные проверки и пересчёты во время программного заполнения формы. После загрузки достаточно одной итоговой проверки. Для проверки вводимого текста можно использовать задержку 200–300 мс, а перед сохранением проверять сразу.

Критерий: непрерывно набрать и удалить 100 символов в каждом поле, включая пароль; курсор и выделение остаются на месте. Повторить с открытыми расширенными настройками, прокруткой и масштабом Windows 100%, 125%, 150%, 200%.

### Пересчёт размеров запускает другие пересчёты

**Приоритет: средний. Риск лишней перерисовки подтверждается структурой обработчиков.**

Источник: `lwtt_manager.ps1`, `Update-EditorResponsiveLayout` (3267), обработчики `Resize` около строки 3630.

Пересчёт вызывается формой, областью прокрутки и нижней панелью. Он сам меняет размеры этих элементов, а также повторно вызывает пересборку сетки через `Update-EditorContentLayout`.

Исправление: единый отложенный пересчёт через `BeginInvoke`, защита от повторного входа, изменение размеров только при отличии от текущих значений. Не фиксировать минимальную ширину содержимого без проверки доступности на небольших экранах и при высоком DPI.

Критерий: изменение размера окна не вызывает каскада пересборок; все поля и кнопки доступны без перекрытий.

## Сохранность изменений и профилей

### Повторное открытие менеджера уничтожает прежнее окно

**Приоритет: высокий. Принудительное завершение подтверждено кодом.**

Источник: `lwtt_tray.ps1`, `Start-ServerManager` (387); `lwtt_common.ps1`, `Close-LikewebServerManagerWindows` (1437).

При открытии менеджера из трея прежний процесс завершается через `Stop-Process -Force`, при необходимости через `taskkill`. Обработчик закрытия с предложением сохранить изменения не получает возможности штатно отработать. Кроме потери ввода, это опасно во время проверки сервера.

Исправление: один экземпляр менеджера с переключением страниц через IPC, например именованный канал. Повторное открытие поднимает существующее окно. Переход на другую страницу проходит через проверку несохранённых изменений. Принудительное завершение оставить только для отдельного восстановления после зависания.

### Создание нового сервера может сбросить текущий ввод

**Приоритет: высокий. Отсутствие проверки подтверждено кодом.**

Источник: `lwtt_manager.ps1`, `Show-NewServerPage` (1962), горячая клавиша Alt+A.

Метод сразу вызывает `Reset-Editor`, хотя пользователь может находиться в изменённом редакторе. Добавить общую проверку переходов, используемую также кнопками назад, закрытием окна и командами трея.

Критерий для обоих пунктов: изменить поле, повторно открыть менеджер, нажать Alt+A, закрыть окно. Ни один сценарий не теряет ввод без явного решения пользователя.

### Сохранение заново создаёт конфигурацию и теряет дополнительные настройки

**Приоритет: высокий. Подтверждено кодом.**

Источник: `lwtt_manager.ps1`, `Get-EditorToml` (1380), `Save-EditorProfile` (2124); `lwtt_common.ps1`, `New-LikewebProfileToml` (747).

Редактор читает ограниченный набор полей и затем создаёт новый TOML по шаблону. Ручные исключения, DNS, маршруты и другие дополнительные параметры заменяются значениями шаблона. При сохранении активного профиля без переподключения файл меняется, но работающий процесс продолжает использовать прежнюю конфигурацию.

Исправление: отделить модель профиля от модели редактора; сохранять неизвестные параметры. Предпочтительно применять совместимый с PowerShell 5.1 TOML-парсер с сохранением семантики документа. Определить явную политику применения: «Сохранено; для применения требуется переподключение» либо «Сохранить и переподключить».

### Обратное преобразование строк TOML может менять пароль

**Приоритет: высокий. Ошибка порядка замен видна в коде.**

Источник: `lwtt_common.ps1`, `ConvertFrom-LikewebTomlString` (328).

Последовательные замены `\n`, `\r`, `\t`, кавычек и обратных слешей не различают экранированный слеш и начало управляющей последовательности. Например, буквальные символы обратного слеша и `n` в пароле записываются как `\\n`, а при чтении могут превратиться в слеш и перевод строки.

Исправление: последовательный разбор escape-последовательностей либо TOML-парсер. Проверить обратимость для паролей с `\n`, `\t`, `\"`, двойными слешами, кириллицей и пробелами. Не выводить реальные пароли в диагностические сообщения.

### Несколько связанных файлов записываются без общей транзакции

**Приоритет: высокий. Подтверждённый риск частичного сохранения.**

Источник: `Save-EditorProfile` (2124), `Set-LikewebActiveProfile` (1036).

Профиль, сертификат, активная конфигурация и указатель активного профиля изменяются по очереди. При переименовании старые файлы удаляются до завершения всех действий. Ошибка доступа, сбой записи или прерывание процесса могут оставить частично обновлённое состояние.

Исправление: подготовить и проверить временные файлы, сохранить резервную копию, заменять файлы атомарно там, где позволяет файловая система. Для набора файлов нужен журнал операции и восстановление при следующем запуске. Старый профиль удалять после успешного завершения. Разделить сообщения об ошибке сохранения и ошибке подключения.

## Надёжность подключения и проверки серверов

### Тайм-аут проверки может прервать восстановление соединения

**Приоритет: высокий. Принудительное завершение и зависимость восстановления от worker подтверждены кодом.**

Источник: `lwtt_manager.ps1`, `Stop-TestWorker` (2217), `Poll-ServerTest` (2332), обработчик `FormClosing`; `lwtt_test_worker.ps1`, блок `finally`.

Через 50 секунд менеджер завершает worker методом `Kill()`. Закрытие формы также вызывает `Stop-TestWorker`. Предыдущее подключение восстанавливается внутри worker, поэтому принудительная остановка не гарантирует выполнения восстановления. Последовательные ожидания остановки, запуска и восстановления могут суммарно превысить 50 секунд. В ветке «worker завершился без результата» восстановление при этом без проверки объявляется успешным.

Исправление: кооперативная отмена с отдельной фазой восстановления, журнал исходной конфигурации до сетевых изменений, проверка результата восстановления менеджером. Тайм-аут должен учитывать этапы операции. Не считать восстановление успешным при неизвестном результате. При аварийном завершении предлагать восстановление из журнала на следующем запуске. Удалять временные файлы с учётными данными также после отмены UAC и ошибки запуска.

Критерий: закрытие окна, отмена, авария worker и тайм-аут не оставляют тестовую конфигурацию активной; восстановление либо подтверждено, либо пользователю показано точное состояние и доступно действие восстановления.

### Переключение продолжает работу после неудачной остановки

**Приоритет: высокий. Подтверждено кодом.**

Источник: `Connect-ProfileById` (1814), `Save-EditorProfile` (2124), `lwtt_tray.ps1`, `Switch-ToServerAndConnect` (335); worker проверки.

В нескольких местах результат `Stop-LikewebVpnAndWait` отбрасывается через `[void]`. Конфигурация после этого заменяется, даже если прежний процесс остался работать. Его наличие затем может быть принято за успешное подключение к новому серверу.

Исправление: обязательная проверка остановки до изменения активной конфигурации. При неудаче сохранять старое состояние и показывать причину. Централизовать переключение и откат в одной операции.

### Наличие процесса принимается за работающее VPN

**Приоритет: высокий. Подтверждено кодом.**

Источник: `lwtt_common.ps1`, `Start-LikewebVpnAndWait` (1570), `Get-LikewebProcess` (1115); `lwtt_tray.ps1`, `Update-TrayStatus` (252).

Процесс, проживший восемь секунд, считается успешным подключением. Это не подтверждает авторизацию, создание туннеля и прохождение трафика.

Исправление: отдельные состояния «процесс запущен», «подключение», «туннель готов», «ошибка», «восстановление». Источник готовности выбрать по возможностям закреплённой версии движка: подтверждённое событие журнала или API. Дополнительная проверка доступа через туннель должна отличать сбой одного проверочного узла от отказа всего VPN и не создавать незаметную постоянную телеметрию.

### Операции трея и менеджера могут пересекаться

**Приоритет: высокий. Риск следует из отсутствия общей блокировки операций.**

Источник: `Set-LikewebOperationState` (1299), синхронные ожидания с `Application.DoEvents`, `Connect-ProfileById`, worker проверки.

JSON-файл состояния информирует интерфейс, но не блокирует параллельное изменение конфигурации. Mutex трея защищает от второго трея, а не от действий отдельного менеджера и worker. `DoEvents` позволяет другим обработчикам исполняться внутри незавершённой операции.

Исправление: один координатор подключения с общей межпроцессной блокировкой и идентификатором операции. Отдельно блокировать изменение профилей во время проверки. Сетевые ожидания вынести из UI-потока; интерфейс обновлять через очередь событий. Завершение старой операции не должно сбрасывать статус новой.

### Остановка может затронуть другой экземпляр TrustTunnel

**Приоритет: средний. Подтверждено кодом.**

Источник: `lwtt_stop.bat:21`, `Get-LikewebProcess` (1115).

Остановка использует `taskkill /IM trusttunnel_client.exe /F`; определение процесса допускает первый найденный процесс как запасной вариант. Это может затронуть экземпляр из другой установки.

Исправление: хранить PID, время старта и путь процесса; сверять принадлежность экземпляра перед управлением. Массовую остановку по имени не использовать в обычной кнопке отключения.

## Общий список обхода VPN

**Статус: согласовано с владельцем, включено в план.**

Пункт «Обход VPN» в трее открывает отдельное окно с переключателем включения, многострочным списком и кнопкой «Сохранить и применить». Один домен, IP или CIDR на строку. Список общий для всех серверов. При выключенном VPN применяется к следующему запуску; при включённом выполняется управляемое переподключение.

- [x] Хранить список отдельно от профилей, в `lwtt_app/settings/bypass.json` вместе с признаком включения.
- [x] Проверять домены, маски поддоменов, IPv4/IPv6 и CIDR; удалять дубликаты. Показывать номер ошибочной строки. Для вставленного URL предложить извлечение домена с понятным результатом.
- [x] Формировать `exclusions` верхнего уровня при `vpn_mode = "general"`. Не подменять этим списком `excluded_routes`, где сейчас находятся исключения локальных сетей.
- [x] Применять список централизованно при каждом запуске и переключении сервера, включая проверку сервера; редактирование профиля не должно его стирать.
- [x] Определить миграцию вручную заданных исключений: сохранять их и объединять с общими, показывая пользователю источник правил. Не заменять существующий список молча.
- [x] Сохранять список независимо от успеха переподключения; при ошибке показывать, что правила сохранены, но ещё не применены.
- [x] Исключить локальные настройки из Git и публичных архивов. Обновить оба сборщика, чтобы пользовательский `bypass.txt` случайно не попал в релиз.
- [ ] Проверить на закреплённой версии движка домен, основной домен вместе с маской поддоменов, IPv4, IPv6 и подсеть. Проверить браузер с обычным и защищённым DNS, HTTP/2 и HTTP/3. Работа доменных правил в этих режимах требует практической проверки.

Поддержка `exclusions` и режима `general` есть в [официальной документации TrustTunnel v1.0.49](https://github.com/TrustTunnel/TrustTunnelClient/blob/v1.0.49/trusttunnel/README.md#exclusions-syntax). Обновлять движок ради появления самого списка не требуется.

## Валидация и понятные ошибки

- **Адрес и порт.** `Normalize-LikewebAddress` (478) допускает порт из любых 1–5 цифр, включая 0 и 99999, и не проверяет содержимое IPv6-скобок. Проверять порт 1–65535 и корректность IP/домена. Сообщать об ошибке в конкретном поле.
- **Импорт сообщения.** `Get-LikewebFieldAfterLabel` (354) берёт следующую непустую строку, даже если это метка следующего поля. При пропущенном адресе может получить слово `Username`. Добавить распознавание границ полей и диагностику пропусков.
- **Сертификат.** Проверяется окончание срока `NotAfter`, но начало `NotBefore` не участвует в валидации. Добавить проверку начала срока. Нормализовать hostname один раз: сейчас проверка сертификата допускает URL, а в TOML сохраняется исходное значение поля.
- **Недоступный профиль.** `Get-LikewebProfiles` (974) молча пропускает профили, чтение которых завершилось исключением. Показывать повреждённый профиль с действием восстановления и писать конкретную причину в журнал.
- **Технические сообщения.** Совет запустить `lwtt_start.bat` вручную мало помогает, поскольку скрипт скрывает процесс и вывод. Давать кнопку просмотра последнего журнала и краткую причину ошибки.

## Сборка и несоответствия документации

1. **Ошибка Windows-сборки.** В `tools/build_bundle.ps1:88–89` используются `Copy-Item -LiteralPath` с путём `*`. Звёздочка трактуется буквально. Перебирать файлы через `Get-ChildItem -LiteralPath` и копировать их по точным путям либо использовать `-Path` там, где раскрытие маски намеренно. Проверить сборку на Windows.
2. **Разные архивы из двух сборщиков.** PowerShell кладёт инструкцию внутрь `lwtt_app`, WSL размещает её рядом с запуском. Согласовать корень архива: запуск, краткая инструкция, папка приложения. Проверять единый список обязательных файлов.
3. **Версия движка не закреплена.** Оба сборщика скачивают `releases/latest`. Добавить параметр версии с закреплённым значением по умолчанию, проверку доступной контрольной суммы или подписи источника и запись версии в `BUILD_INFO.txt`. Обновление движка проводить отдельно от сборки оболочки.
4. **Устаревшие версии в текстах.** `VERSION` и код содержат 4.16, `CHANGELOG.md` заканчивается 4.15, `docs/RELEASE_RU.md` называет текущим архив 4.15 и описывает старое плоское расположение файлов. Использовать один источник версии и обновлять инструкции вместе со структурой архива.
5. **Пути к данным в инструкциях.** Явно указывать `lwtt_app/profiles`, `lwtt_app/log`, `lwtt_app/lwtt_client.toml`. В инструкции обновления описать перенос данных из старого плоского размещения и резервное копирование до переноса.
6. **Запуск из папки с пробелами.** В `lwtt_tray.ps1`, `Start-ServerManager`, путь после `-File` передаётся элементом массива без явного quoting. `Start-Process` соединяет массив в строку; отдельный элемент не гарантирует сохранения пробелов. Исправить общий механизм аргументов и проверить путь `C:\VPN Apps\LWTT`, кириллицу и апостроф. Аналогично проверить BAT-команды повышения прав.
7. **Пунктуация.** В документации и отдельных строках кода остался символ U+2014. В пользовательских текстах заменить его на U+2013. В парсере при необходимости сохранить распознавание старого разделителя через `\u2014`, чтобы не сломать импорт прежних сообщений.

## Постепенный рефакторинг

Переписывание всего приложения не требуется для первых исправлений. Сначала стабилизировать поведение, затем выделять части с сохранением совместимости PowerShell 5.1.

| Часть | Ответственность |
| --- | --- |
| Профили | Чтение модели, проверка, безопасное сохранение и миграция |
| Конфигурация TrustTunnel | TOML, DNS, сертификаты и применение общих исключений |
| Подключение | Единственная очередь запуска, остановки, переключения, теста и отката |
| Интерфейс | Создание контролов, события, отображение состояния и размещение |
| Диагностика | Причины ошибок, ротация журналов, очистка секретов при экспорте |
| Сборка | Закреплённые зависимости и единые правила состава архивов |

Уменьшить использование глобальных `$script:`-переменных через явные объекты состояния. Убирать пустые `catch` в значимых операциях: ожидаемые ошибки обрабатывать, неожиданные записывать с контекстом. При длительной эксплуатации добавить ограничение объёма журналов и очистку старых тестовых файлов с учётом незавершённых операций.

## Проверки перед выпуском

Добавить небольшие целевые проверки для TOML-строк, импорта сообщений, адресов и портов, сохранения дополнительных настроек и применения bypass. Для управления процессами проверять отказ остановки, ошибку запуска и откат через подменяемый слой запуска, без настоящего VPN.

На Windows вручную проверить непрерывный ввод, Tab и выделение текста; изменение размера окна и DPI; отмену UAC; повторное открытие менеджера; закрытие окна во время теста; одновременные команды из трея и менеджера; запуск из папки с пробелами; переключение при недоступном сервере; обновление приложения с сохранением профилей.

Релизный архив проверять на состав, целостность, совпадение скриптов с исходниками и отсутствие пользовательских данных. Проверки синтаксиса PowerShell выполнять без запуска приложения и без изменения сетевых настроек. Полную проверку подключения выполнять на отдельной Windows-машине с тестовым профилем.

## Технические источники

- [WinForms ControlCollection.Clear](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.control.controlcollection.clear): удаляет элементы из коллекции родителя; это не обычное обновление размеров.
- [Process.Kill](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.kill): принудительное завершение может привести к потере изменяемых данных и не заменяет штатную отмену.
- [Start-Process в PowerShell 5.1](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/start-process?view=powershell-5.1): правила передачи аргументов и кавычек для путей с пробелами.
